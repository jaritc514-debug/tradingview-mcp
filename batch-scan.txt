BATCH PREFILTER — HTF Supply & Demand
=====================================
Scan your entire TradingView watchlist for HTF Supply & Demand zones.
Do NOT run full analysis. Do NOT calculate entry levels beyond the quick 2R check below.
See rules.json for the full rulebook.

Run about twice a week (before market open, and midweek) — scope is intentionally bounded per
rules.json zone_detection.scan_scope: Weekly nearest 2 Supply + 2 Demand (any freshness — confluence only).
Daily nearest 3 FRESH Supply + 3 FRESH Demand — Touched Daily zones aren't entry candidates, skip them.

---

STEP 0 — PULL THE WATCHLIST
- Before running: make sure the "SCAN" watchlist tab is the active one in TradingView's right-hand panel.
  watchlist_get reads whichever watchlist tab is currently visible — it does not know about or combine
  other watchlists. If a different tab is active, this will silently scan the wrong (or empty) list.
- watchlist_get → the actual live symbol list. Scan every symbol returned, in the order given.
- Do not assume or hardcode a symbol list — always use what watchlist_get actually returns.

FOR EACH SYMBOL — run silently, no mid-scan output:

1. chart_set_symbol → switch to symbol

2. WEEKLY PASS
   - chart_set_timeframe → Weekly
   - data_get_study_values() → "Supply N Proximal/Distal" / "Demand N Proximal/Distal" for Supply & Demand
     Pro, ordered nearest-to-farthest. Keep Supply 1-2 and Demand 1-2 only, regardless of freshness
     (fewer if fewer exist).
   - data_get_pine_boxes(study_filter="Supply & Demand Pro", verbose=true) +
     data_get_pine_labels(study_filter="Supply & Demand Pro") → match by price to the kept zones for
     formation (RBD/RBR/DBR/DBD), F, O, LoL, and freshness (#1c1c2e=Fresh, #787b86=Touched — see
     rules.json indicator_tags.freshness_detection).
   - If unreadable: flag pair as UNREADABLE, skip to next symbol

3. DAILY PASS
   - chart_set_timeframe → Daily
   - data_get_study_values() again — may return more than 3 per side. Match ALL against pine_boxes/labels
     for freshness, then keep only the nearest 3 FRESH Supply and nearest 3 FRESH Demand (skip Touched
     ones, keep checking further down the list; fewer than 3 if fewer than 3 Fresh exist — no fallback to
     Touched, no padding).

4. HTF COVERAGE
   For each in-scope Daily zone, check if it sits inside or overlaps an in-scope Weekly zone of the same
   type. HTF Coverage = Yes / No. Report both either way — not a filter.

5. LEG-OUT QUALITY — DAILY ZONES ONLY
   Weekly zones never get a risk tier or Entry/SL/TP, so skip this step entirely for them — don't fetch
   Weekly OHLCV or classify Weekly breaking candles, that's wasted work for a value that's never used.
   Base length already filtered by the indicator (max 6 candles) — do not re-validate.
   For each in-scope DAILY zone, pull candles via data_get_ohlcv around its formation and classify the
   breaking candle: ≤49% body = indecisive | 50-75% = decisive | >75% (abnormally large) = explosive
   Leg-out quality = Explosive / Decisive. If the fetched OHLCV window doesn't reach the zone's formation,
   report "not computed" rather than guessing.
   Also classify the candle right after the breaking candle. strong_leg_out = TRUE if the breaking candle
   is Explosive, OR if the breaking candle AND the next one are BOTH Decisive — only matters for the 2%
   tier (Step 9), not the plain leg-out quality above.

6. TREND CONFLUENCE (tag only)
   - data_get_pine_tables(study_filter="Trend Direction Pro") → Daily and Weekly rows
   - Tag each zone trend-aligned or trend-conflicting. Never excludes a zone.

7. VALUATION CONFLUENCE (tag only — pick the right indicator per asset, see rules.json)
   - Daily timeframe ONLY — never read valuation on Weekly. Chart should already be on Daily from step 3,
     confirm before this read. One read per symbol.
   - DAILY ROWS ONLY. It's a flat per-symbol reading, identical regardless of which zone — don't attach it
     to Weekly rows in the output table at all, that's misleading clutter, not a per-zone signal. Trend
     still shows on Weekly rows (real input to the 2% tier), valuation does not.
   - Classify each symbol first, then use the matching study_filter — don't try all three per symbol:
       Currency future / FX major / commodity / metal → study_filter="CampusValuationTool" (no spaces)
       Index future (NQ/YM/ES/RTY)                     → study_filter="Supreme Valuation"
       FX cross pair (non-USD)                          → study_filter="MTF Cross Pairs Valuation"
   - data_get_pine_tables(study_filter=<selected above>) or data_get_study_values as fallback
   - Prior UNREADABLE result was likely the wrong name, not a real read failure — retest with the
     corrected names before assuming the pane-visibility theory applies.
   - Convert the raw value to a state per rules.json valuation_confluence.classification:
       >= 75 Extreme Overvalued | 0.5 to 74.99 Overvalued | -0.5 to 0.5 Neutral
       -74.99 to -0.5 Undervalued | <= -75 Extreme Undervalued
   - Report the classified state per symbol, or "unreadable" if the read still fails. Never excludes a zone.

8. PROFIT CHECK (2R-based) — DAILY ZONES ONLY
   Weekly is never entered directly — it's an odds-enhancer for HTF Coverage only. Skip this step for
   Weekly zones; their Path/Risk Tier columns in the output table are "—".
   Entry = proximal edge. SL = distal edge + 33% of zone height buffer (away from the zone, direction per
   rules.json risk_rules.stop_loss). TP = entry ± 2R (fixed). Check if an opposing in-scope Daily zone sits
   between entry and the 2R target.
   Path = Clear / Boxed in.

9. RISK TIER — DAILY ZONES ONLY
   Check top-down against rules.json risk_tiers — highest tier whose conditions are FULLY met:
     2% (All Stars Aligned): HTF Coverage Yes AND strong_leg_out TRUE AND Weekly trend aligned with
       direction (Daily aligned too is a bonus, not required) AND Extreme Undervalued (Demand/buy) or
       Extreme Overvalued (Supply/sell). All four required, or fall through to the tiers below.
     1.5%: Explosive or Decisive leg-out, HTF Coverage present
     1%: Decisive+ leg-out, no HTF Coverage
     0.5%: everything else that still clears the basic checklist
   No tier for Weekly zones — see rules.json risk_tiers.scope_note.

---

OUTPUT — print after every symbol on the watchlist has been scanned:

SORT ORDER (Daily zones — these are the ones with a tier to sort by):
1. Tier 2% (All Stars Aligned) — highest conviction, always first
2. HTF Coverage: Yes, tier 1.5%
3. HTF Coverage: Yes, tier 1% or 0.5%
4. HTF Coverage: No, any tier — still real zones, just no Weekly confluence
5. UNREADABLE — always last, separated by divider
Weekly zones (no tier) — group directly under their pair's Daily rows, order doesn't otherwise matter.

TABLE FORMAT (one line per zone — a pair may appear more than once, up to 2 Weekly + 3 Daily zones per side):
[PAIR] | [Weekly/Daily] | [Supply/Demand — formation] | [Fresh/Touched] | [Leg-Out] | [HTF Coverage] | [Trend tag] | [Valuation state] | [Path] | [Risk Tier]
Weekly rows: Leg-Out, Valuation, Path, and Risk Tier are always "—" (not traded directly, confluence-only
— leg-out isn't computed and valuation isn't attached for Weekly zones at all, see Steps 5 and 7).
Valuation is read once per symbol on the Daily timeframe only (never Weekly, see Step 7) — reuse that
same read across all of that pair's Daily rows, but never show it on that pair's Weekly rows at all.
